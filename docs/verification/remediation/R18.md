## 1. What changed

### 1.1 Interfaces (spec §9, in `research/run_experiments.py`)

- `EvaluationMetrics` — frozen record of the recorded metric values
  (precision/recall/f1/pr_auc/fpr_ratio/latency_p95_ms, sample sizes,
  confusion, 95% CIs); `fpr_per_1000` derived property; `from_metrics_dict`
  for the runner/CLI.
- `EvaluationPolicy` — resolved from `research/protocol.json`
  `acceptance_gates`; `__post_init__` enforces the spec §9 hard minima
  (recall 0.85, FPR 50/1000, PR-AUC 0.80, p95 25 ms): a protocol may tighten,
  never loosen (ValueError otherwise).
- `evaluate_gate(metrics, baseline, policy) -> GateDecision` —
  `GateDecision(research_status, activation_allowed, reasons, claim)`.
  Statuses `PASSED | FAILED | INSUFFICIENT_DATA`. Missing class or empty
  sample -> INSUFFICIENT_DATA (the gate refuses instead of dividing
  silently). Activation rule: research PASSED AND recall >= baseline AND
  FPR <= baseline AND strict gain in at least one (baseline FPR = 0 forbids
  a false-positive-reduction claim when FPR rose).
- `generate_claim_text` — the claim is GENERATED from the decision; no
  constant SUPPORTED string exists anywhere in the decision path.
- `build_evaluation_seal` / `verify_evaluation_seal` — the seal covers
  labels_sha256, predictions_sha256, config_hash, split_hash, model_hash,
  evaluated_at and a seal_hash over the canonical body.

### 1.2 Metrics (replaces the T19 computation for the runner)

- `compute_eval_metrics` — confusion matrix (tp/fp/fn/tn + nested
  `confusion`), class-completeness flags, sample sizes, 95% Wilson intervals
  (`wilson_ci95`, pure Python) for precision/recall/FPR, p95 latency.
- Honest zero-denominator semantics: precision with tp+fp=0 -> 0.0 (not
  1.0); recall with tp+fn=0 -> 0.0; FPR with fp+tn=0 -> None (never a fake
  0.0 "success"); `has_positives`/`has_negatives` let the gate refuse.
- `compute_average_precision` — AP with score TIES GROUPED into single
  threshold blocks (permutation-invariant); reported as `pr_auc` (AP), by
  name, and cross-checked against scikit-learn `average_precision_score`
  in tests. FPR ratio kept unrounded internally (gate arithmetic), display
  per 1,000 via `format_fpr` (`1.57/1000 (0.157%)`).

### 1.3 Runner (`run_experiment_suite`) and CLI

- Config loading via `load_experiment_config`: `research/protocol.json`
  remains the single source; the new `research/experiment-config.json` is a
  thin shim (`{"protocol": "protocol.json"}`) whose unknown keys are
  rejected. `validate_protocol_config` fails closed (cutoffs parse and
  order, no random-split fallback, models present, gates numeric AND not
  loosened below/above the spec floors, label column present).
- Config errors raise `ProtocolConfigError` and crash loudly
  (`[R18][CONFIG-ERROR]` + traceback) — they are NEVER recorded as the
  INSUFFICIENT_DATA taxonomy (R17 deferred minor).
- The accepted path computes `evaluate_gate` (hybrid candidate vs rules
  baseline vs policy), builds the evaluation seal over y_test/hybrid_preds,
  and records `outcome = gate_decision.research_status`, `model_id`,
  `model_artifact_path`, `gate_decision` (with generated claim) and
  `evaluation_seal` in the run manifest. The old inline
  `supported = ...; outcome = "SUPPORTED"` block is gone.
- `--check-gate` (with `--run-dir` optional): verifies the seal, the seal/
  manifest fingerprint match, and that the artifact the server will load
  (`model_artifact_path`) hashes to the manifest `model_hash`; reproduces
  the decision from the recorded `metrics_by_model`; exits **0** PASSED +
  activation approved, **1** FAILED (or PASSED but activation denied),
  **2** INSUFFICIENT_DATA / environment cannot reproduce (missing manifest,
  tampered seal, artifact missing/mismatched, non-reproducing decision).
- `_write_evaluated_readme` (replaces `_write_accepted_readme`): table with
  95% CIs, PR-AUC labeled "(AP)", FPR in both units, confusion matrices,
  sample sizes, the generated claim, reasons, the seal, and the
  synthetic-data caveat.
- `research/experiment-manifest.schema.json`: outcome enum now
  `PASSED|FAILED|INSUFFICIENT_DATA`; adds `model_id`,
  `model_artifact_path`, `gate_decision`, `evaluation_seal`, `protocol_path`
  (required for PASSED/FAILED via if/then-else).

### 1.4 Model registry binding (`ai-engine/app/models/registry.py`)

- `ModelRegistry(server_model_path, binding_path)` — defaults to the
  server's load path `app/models/pretrained/fraud_model.joblib` and the
  binding file `app/models/pretrained/active_model.json`.
- `activate(model_id, run_manifest_path)`: refuses (fail-closed
  `ModelActivationError`) unless the manifest records research_status
  PASSED with activation_allowed, the seal reproduces and pins the
  manifest's config/split/model fingerprints, the requested model_id is the
  evaluated one, and the artifact at the server path hashes to the
  manifest `model_hash`. Success writes an atomic activation binding.
- `binding_status()` -> `UNBOUND | ACTIVE | BROKEN`; `active_binding()`;
  `resolve_engine(requested_mode)`: `rule_based` always rule_based;
  `auto` (default) hybrid only with a fully valid binding, else the
  declared rule_based default; `hybrid` without a valid binding raises
  (operator-requested hybrid with a non-gated model fails clearly — no
  undeclared fallback). A binding whose manifest file changed (threshold
  retune) or whose artifact was swapped is BROKEN and raises until a NEW
  sealed PASSED run is bound.

### 1.5 Assessment service (`ai-engine/app/services/assessment_service.py`)

- `AssessmentService(feature_service, model_registry, requested_engine)`:
  resolves the engine through the registry at the start of every
  assessment; default `auto` -> rule_based; `requested_engine="hybrid"`
  without a valid binding raises `ModelActivationError` (clear request
  failure). `model_loaded` remains truthfully False (this authoritative
  path evaluates the regulatory rule matrix).

### 1.6 R17 deferred minors fixed (opportunistic, authorized)

- Config-error path now crashes loudly (ProtocolConfigError) instead of

- `research/tests/test_splits.py::test_run_pipeline_reports_insufficient_data_honestly`

  (`run_experiments.MODEL_ARTIFACT_RELPATH` =
  `ai-engine/models/pretrained/fraud_model.joblib`) is neither created nor
