## 5. Snapshot semantics / classification notes (spec §5)

- Pin: `block_number = latest - confirmation_depth + 1` (local depth 2, institutional default 12 from the registry), `block_hash` pinned; every `eth_call/eth_getCode/eth_getLogs/read_incident` executes at the pin (journal-proven by `all_reads_use_same_block`); the pin is re-checked before the verdict — reorg to another hash → `unavailable: snapshot_reorged`.
- A later append never disturbs a prior valid snapshot: re-verification with `snapshot_id` re-reads at the SAME pin (entries beyond the pin are invisible by construction) — `append_preserves_snapshot`, `current_head_not_snapshot_head`.
- Writer authorization replays `EvidenceWriterUpdated` from `deployed_at_block` ordered by `(blockNumber, transactionIndex, logIndex)` strictly BEFORE the append event — same-block add-then-revoke stays valid, revoke-then-add invalidates, grant-after-submit does not authorize; end-of-block state is never consulted. Missing history → `unavailable: historical_logs_unavailable` (never the current allowlist).
- Manifest commitment: SHA-256 of the stored canonical SIGNED envelope must equal `getManifestDigest`/the anchored event; the anchor block timestamp is the PROVEN `trusted_time` for lifecycle checks (retired keys verify with anchor-time proven; without provable time → `unavailable: historical_key_time_unproven`).
- Honest classification, never fabricated `verified`: unsigned legacy rows → `invalid: legacy_unattested`; automated AuditEngine traces (no anchored commitment) → `invalid: chain_generated_unattested`.
- V3 accepts only `case_id`/`evidence_ids`/`snapshot_id`; identifiers are strings referencing `EvidenceObject`; on-chain uint256 values are emitted as decimal STRINGS. V2 verify in institutional mode returns **410** with the V3 pointer; demo keeps the local tool (non-official provenance).
- `VerificationSnapshot` persisted in `verification_snapshots` (block hash, head/count at pin, checked ids, status/reasons) and REUSED verbatim by `snapshot_id`.
