## 1. What changed

`contracts/access/RoleManager.sol` exposed `testSetGeneration(address,uint256)` with **no
authorization** (old lines ~312–317). It wrote `_generations[_target] = _gen` directly — the
same security generation that `MultiSigApproval.executeProposal` compares against
`_approverGenerations` when deciding whether recorded votes are still fresh. Any external
address could therefore forge or reset a participant's generation and invalidate/validate
governance votes at will.

Removed (7 lines, exact text):

```solidity
    /**
     * @notice Test helper to simulate authorization generation change / revocation
     */
    function testSetGeneration(address _target, uint256 _gen) external {
        _generations[_target] = _gen;
    }
```

- Removed selector for the record: `testSetGeneration(address,uint256)` = `0x9d043203`.
- Spec-mandated views preserved untouched: `getGeneration(address)->uint256` and
  `getParticipant(address)->(bytes32,uint256,Role,bool)`.
- Generations can now only change through the real paths: `assignRole` / `revokeRole`
  (both `onlyGovernance`, each `_generations[_target]++`), plus the constructor bootstrap.
- `contract_version` remains **2.0.0** (2.1.0 belongs to R03/R04; no version bumped here).
- No other RoleManager logic touched (diff is 7 deletions, 0 insertions in the contract).

### Caller migration

`test/security/GovernanceExecution.test.js` ("should invalidate previous votes if an
approver's role was revoked before execution") previously drove the scenario with
`roleManager.connect(admin).testSetGeneration(auditor2.address, 2)`. It now uses the real
governance path: a `ROLE_CHANGE` proposal targeting `roleManager.revokeRole(auditor2, …)`
is created by `auditor1`, approved by `admin` + `auditor2` (2-of-2), and executed
atomically via `multiSig.executeProposal` — `revokeRole` is `onlyGovernance` and governance
is the MultiSig contract. The executed revocation bumps auditor2's generation and deactivates
them, so the later `executeProposal(1)` still reverts with
`"MultiSig: approver authorization generation is stale or revoked"` — identical regression
coverage, no artificial state mutation. `test/RoleManager.test.js` and
`test/security/ObservedRegressions.test.js` never call the removed function (verified by
`findstr`, no edits needed).
