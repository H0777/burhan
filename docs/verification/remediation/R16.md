## 1. What was fixed (F12 Closure)

1. **Encrypted Backup Creation & Signed Envelope:**
   - `BackupService.create_backup()` generates AES-256-GCM encrypted database snapshots with random DEK wrapped by institutional keys via `KeyProvider`.
   - Emits a cryptographic manifest signed by `Signer` under domain `AML_BACKUP_V1` with Ed25519.
   - Raw snapshot bytes are encrypted at rest without leaking SQLite headers or plaintext tables.

2. **Cryptographic Hash Integrity Chain:**
   - Every backup record links to `prev_backup_hash`, establishing an unbroken hash chain across snapshots.
   - `BackupService.verify_chain()` mathematically validates sequence continuity and raises `ChainIntegrityError` if any intermediate link is modified, skipped, or reordered.

3. **Snapshot Verification & Tamper Detection:**
   - Restores fail-closed (`BackupCorruptionError`): verifies archive path hygiene (rejecting Zip-Slip `../../` path traversal), manifest signatures against `TrustRegistry`, ciphertext integrity, GCM auth tags, and SHA-256 file hashes before committing any state to target database.
   - Bit-rot, manipulated manifests, altered evidence, and forged signatures are actively rejected.

4. **Crash Recovery & Clean Resource Disposal:**
   - Atomic staging prevents partial residue: failures midway through backup automatically clean temporary staging directories.
   - Source and target database engines are explicitly disposed in `finally:` blocks to prevent SQLite file locks on Windows.
   - State reconciliation restores and verifies exact record counts, pending Outbox entries, and Checkpoint block heights.

5. **WORM Immutability & Tamper-Evident Audit Logs:**
   - Both `BackupService` and `EvidenceStore` enforce strict immutability, rejecting overwrite attempts (`FileExistsError` / `ValueError`).
   - `EvidenceStore` records immutable operational audit logs (`PUT`, `OPEN`, `OVERWRITE_REJECTED`, `TAMPER_DETECTED`) to disk (`.audit_logs.jsonl`) and memory.
