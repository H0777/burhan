## 1. What changed

### 1.1 Partitioning policy (spec §9, implemented verbatim in `research/run_experiments.py`)

- `partition_splits(records, train_end, validation_end, *, seed=42, min_split_size=100, require_both_classes=True) -> SplitManifest`.
  - `train` = records with `occurred_at <= train_end`.
  - `validation` = ONLY participants with `first_seen > train_end` AND `last_seen <= validation_end`, and their in-window records.
  - `test` = ONLY participants with `first_seen > validation_end`, and their later records.
  - Later records of train participants → dropped with `TRAIN_PARTICIPANT_FUTURE_RECORD`; any participant crossing the validation/test boundary → ALL their records dropped with `PARTICIPANT_CROSSES_VALIDATION_TEST_BOUNDARY` (enters neither evaluation set). No future record is ever migrated into training to compensate size.
  - Every source ID lands in exactly one split or carries exactly one recorded drop reason (`compute_partition_plan` is a pure function; both `partition_splits` and `validate_splits` use it).
  - **Fail-closed:** empty source, any split `< min_split_size` (default 100), any split missing label column or missing a class → `SplitValidationError` (carrying the rejected `SplitManifest` as evidence). **There is NO random-split fallback anywhere** (`findstr /s /i "train_test_split ShuffleSplit" research\run_experiments.py` → no matches; the only sklearn estimators are `IsolationForest` and `StandardScaler`).
  - Cutoffs must be UTC-aware; naive timestamps and `train_end >= validation_end` are rejected.
- `validate_splits(manifest, records) -> None` — re-determines the partition from the records and fails closed on: membership mismatch, window violations, actor overlap between any pair of splits, participant-eligibility violations (first/last-seen conditions), coverage gaps (not exactly the source IDs, or a record in two places), missing drop reasons, size/class violations per the recorded policy, source/split fingerprint mismatches, and drop-count mismatches.
- The pre-R17 `partition_splits(records, train_ratio, val_ratio)` (alphabetical sender assignment = temporal overlap by construction) is deleted; the old split-hash (first-50 train/test IDs + lengths) is deleted.

### 1.2 SplitManifest — full fingerprints

- Carries: UTC cutoffs (`train_end`, `validation_end` as `...Z`), `seed`, policy (`temporal_participant_disjoint`, `min_split_size`, `require_both_classes`, `random_split_fallback_allowed: false`, drop reason codes), **all** record IDs per split, participant IDs per split, full drop list + per-reason counts, `accepted` flag + `validation_errors` (for rejected artifacts).
- SHA-256 fingerprints (`0x…`): `source_fingerprint` over the full ordered canonical source list; per-split `fingerprint` over each FULL ordered split list (canonical: sorted by (occurred_at, id), sorted keys, compact JSON) — **never truncated to the first 50 IDs**; `manifest_hash` over the entire serialized manifest excluding only `created_at` (deterministic).
- Serialized form conforms to the new `research/schemas/split-manifest.schema.json`. Rejected manifests are written with `accepted: false` + `validation_errors` and their own `manifest_hash` (pins the evidence).

### 1.3 Feature history + scaler

The generator now calls it instead of computing windows inline — a future event can never influence an earlier record, regardless of input list order.
