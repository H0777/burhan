## 1. What changed

### 1.1 Standalone Verifier CLI (`scripts/verify-evidence-export.py`)

- **Zero App/DB Dependencies**: Works completely offline using Python standard library and `cryptography` (Ed25519) via canonical serialization (`evidence_crypto`).
- **Strict ZIP Traversal and Expansion Limits**:
  - Enforces `member_count <= 1000`, `single_file_limit <= 25 MiB`, `total_uncompressed_limit <= 512 MiB`.
  - Rejects zip-slip traversal (`../`), absolute paths (`/` or `C:`), case-insensitive collisions, and duplicate member paths (exit code 1: `bundle_status: "invalid"`).
- **Authoritative Integrity & Anti-Tampering Checks**:
  - Strict verification of `checksums.sha256` against actual uncompressed bytes.
  - Strict verification of physical evidence items matching declared SHA-256 hashes.
  - Rejection of stubbed evidence files (`EVIDENCE-STUB:`) as invalid.
  - Canonical JSON re-computation and verification of `dossier_hash` and Ed25519 signature over domain `AML_DOSSIER_V1`.
- **Trust Registry & RFC 3161 Verification**:
  - Evaluates institutional trust registry entries (`active`, `revoked`, `retired`).
  - Fails closed with exit code 2 (`bundle_status: "unavailable"`) when registry or public key is missing or when a retired key lacks trusted time.
- **Deterministic Exit Codes**:
  - `0`: Valid bundle (and anchor verified if online).
  - `1`: Tampering detected, missing/extra files, duplicate JSON keys, or archive corruption.
  - `2`: Key unavailable, registry missing, or RPC failure.

### 1.2 Schema & Validation Specification

- **`shared/schemas/dossier-manifest-v1.schema.json`**:
  - Strict JSON schema for court-admissible dossiers under envelope domain `AML_DOSSIER_V1`.
  - Mandates fields: `institution_id`, `key_id`, `schema_version: 1`, `report_id`, `case_id`, `case_number`, `generated_at`, and `files` inventory.
