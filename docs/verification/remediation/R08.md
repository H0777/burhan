## 1. What changed

- **`ai-engine/app/repositories/outbox_repository.py`** — Leased Outbox claim engine:
  - `claim_batch(session, institution_id, worker_id, now, limit=20)`: Uses `SELECT ... FOR UPDATE SKIP LOCKED` on PostgreSQL; leases unowned or expired rows atomically by setting `lease_owner`, `lease_token = uuid4()`, `lease_expires_at = now + 60s`.
  - `renew_lease(session, outbox_id, lease_token, now)`: Extends the lease by 20s conditional on matching `lease_token`.
  - `complete_outbox(session, outbox_id, lease_token)`: Transitions status to `COMPLETED` and clears lease tokens; rejects completion from wrong owner or expired lease.
  - `fail_outbox(session, outbox_id, lease_token, error, now)`: Implements the exponential backoff ladder (5s, 30s, 120s, 600s, 1800s); marks item `DEAD` after 5 failed attempts while preserving error history.
- **`ai-engine/app/services/chain_sender.py`** (new) — Raw transaction and nonce discipline pipeline:
  - `prepare_and_persist(session, binding, call, request_id)`: Allocates tenant-scoped nonce, signs raw EIP-155 transaction locally using `eth_account`, and persists raw transaction in `chain_submissions` table BEFORE any network broadcast.
  - Enforces `UNIQUE(chain_id, signer_address, nonce)` and `UNIQUE(institution_id, request_id, submission_kind)` to guarantee no duplicate submissions or nonces.
  - `broadcast(submission)`: Transmits `protected_raw_tx` over RPC. On crash or network retry, the identical raw transaction and tx_hash are rebroadcast without allocating new nonces.
  - `reconcile(submission)`: Reconciles mined receipt status, confirmation depth, and handles chain reorg (status returned to SUBMITTED if block hash rewinds).
  - Nonce stuck detector: If a transaction remains unconfirmed after 300s, logs an operational alert and pauses new sends for the signer to prevent nonce cascading failures.
- **`ai-engine/app/services/evm_rpc_client.py`** — Send adapter separation:
  - `JsonRpcSendAdapter`: Dedicated transport for broadcast and send-path idempotency checks (`getManifestDigest`, `getEvidenceByRequestId`, `getIncidentByCaseReference`). Never logs or stores private keys.
- **`ai-engine/app/workers/evidence_anchor.py`** — Evidence anchor worker:
  - Fully decoupled from HTTP requests. Processes leased outbox batches, coordinates with `ChainSender`, and anchors evidence using stored `manifestDigest`.
  - Handles crash injection at every stage (after claim, after sign, after broadcast, before DB commit) idempotently.
- **`ai-engine/app/workers/indexer.py`** — Blockchain indexer & heartbeat:
  - Added `record_heartbeat(session, institution_id, worker_id, clock)`: Writes per-worker heartbeat row (`worker_heartbeats`) each cycle with injectable clock for observable monitoring.
  - Idempotent reorg checkpoint rollback without deleting original evidence files or payload JSON.
- **`ai-engine/app/workers/runner.py`** (new) — Operational CLI runner:
  - Supports `python -m app.workers.runner anchor` and `python -m app.workers.runner indexer`.
  - Implements graceful shutdown (SIGINT/SIGTERM), finishing the active task cycle and releasing leases without dropping database integrity.
- **`ai-engine/app/db/migrations/versions/0004_outbox_delivery.py`** (new; slug `0004_outbox_delivery`, `down_revision = "r07_verification_snapshots"`):
  - Adds lease columns to `outbox`: `lease_owner`, `lease_token`, `lease_expires_at`, `next_attempt_at`, `last_error`, `attempts`.
  - Creates `chain_submissions` table with unique constraints on nonce and request_id.
  - Creates `worker_heartbeats` table with primary key `(id)` and index on `(institution_id, role, worker_id)`.

## 2. Historical vulnerability context (why this task exists)

- **Previous state**: Evidence anchoring was triggered directly in HTTP route handlers with a mock EVM client. A process crash, restart, or network hiccup between blockchain broadcast and DB update caused orphaned anchors or inconsistent duplicate records.
- **Nonce collisions**: Multiple parallel worker threads or restarts attempted to reuse nonces or desynchronized with the on-chain account state.
- **Lease starvation / race conditions**: Multiple workers claimed the same outbox events simultaneously without SKIP LOCKED or lease expiration.

## 5. Crash recovery and nonce discipline proof

- **Crash after claim**: Outbox item lease expires after 60s; recovered by secondary worker without duplicating work.
- **Crash after signed tx commit**: Mined on-chain before DB commit is recognized on restart via `getEvidenceByRequestId`, preventing duplicate counter increments or second transactions.
- **Receipt status 0 (EVM revert)**: Mark submission as failed and route to backoff ladder without falsely marking anchor as confirmed.
- **Reorg detection**: If a block is reorganized out, submission status drops from `CONFIRMED` back to `SUBMITTED` until re-mined at sufficient depth.

## 7. Honest limits

- Chain interaction in integration tests uses `SimulatedEvmAdapter` to provide bit-for-bit EVM RLP serialization, cryptographic signing, and ForensicTrail contract deduplication semantics without running a full geth node in CI.
- Production deployments require configured RPC endpoint (`ETH_RPC_URL`) and institution private keys mounted via environment or vault.
