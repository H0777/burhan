## 2. Key Code Changes & Governance Alignment

### 2.1 Manifest Key Normalization
In `tests/e2e/trust-flow.spec.js` and services (`chain_registry.py`, `evm_rpc_client.py`), support was unified for both V3 manifests (`addresses`, `deployed_code_hashes`) and legacy V2 manifests (`contracts`, `code_hashes`):
```javascript
manifest.contracts = manifest.addresses || manifest.contracts;
manifest.code_hashes = manifest.deployed_code_hashes || manifest.code_hashes;
```

### 2.2 R03 Separation of Duties (SoD) & Governance Roster Alignment
The test accounts and voting roles in `tests/e2e/trust-flow.spec.js` were updated to match the production roster bootstrapped in `scripts/deploy.js` (lines 185–212):
- **`signers[0]` (deployer):** Role revoked upon bootstrap finalization; retains NO voting power.
- **`signers[1]` (SUPER_ADMIN):** Proposer for governance actions.
- **`signers[2]` (AUDITOR):** First independent approver.
- **`signers[3]` (AUDITOR):** Second independent approver.
- **`signers[5]` (OPERATOR):** Non-voting participant; voting attempts are rejected with `/caller not authorized to participate/i`.
- **Four-Eyes Principle:** Proposer cannot vote on their own proposal (`/proposer cannot approve own proposal/i`).

### 2.3 R03 Governance Timelock Enforcement
Under R03, `ROLE_CHANGE` and `SYSTEM_CONFIG` proposals mandate an on-chain timelock delay of `86,400s` (24 hours). The E2E test harness now programmatically advances the local Hardhat EVM clock past this boundary before triggering atomic execution:
```javascript
await provider.send("evm_increaseTime", [86401]);
await provider.send("evm_mine");
```
