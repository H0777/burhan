## 1. Remediation Details

1. **Standardized Probe Endpoints:**
   - Root endpoints `/health/live`, `/health/startup`, `/health/ready` mounted alongside `/api/v2/health/*` to satisfy standard Kubernetes / Docker container health checks without extra path prefixes.
   - `/health/live`: Fast process-level liveness probe returning HTTP 200 `LiveHealthResponse(status="live", service="ai-engine")`.
   - `/health/startup`: Startup completion probe that validates configuration invariants (`validate_startup_config`), database connectivity, schema migration status, and evidence vault storage writeability before the container accepts traffic.
   - `/health/ready`: Subsystem and dependency readiness probe, covering live DB, migration revision, KMS/vault, EVM RPC responsiveness, ML engine, and policy service.

2. **Prevention of Startup Dependency Cycles:**
   - Startup probe verifies foundational layers (DB, migrations, vault) independently of background worker heartbeats, preventing cyclic boot dependencies between API and workers.
   - Failing startup invariants explicitly sets HTTP 503 and `ready=False` with diagnostic error messages.
