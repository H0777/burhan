# خطة تنفيذ الإصلاحات الدقيقة — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** إغلاق العيوب المثبتة في المراجعة، وتقديم نسخة يمكن اختبارها مؤسسياً دون نتائج تحقق أو جاهزية غير مسندة.

**Architecture:** إصلاح العقود والخادم والواجهة الحالية تدريجياً مع عقد ثقة واحد للهوية والنشر والأدلة. العقود المعدلة تُنشر محلياً بإصدار جديد، وتبقى السجلات القديمة قابلة للفحص التاريخي.

**Tech Stack:** Solidity 0.8.20/Hardhat 2، Python/FastAPI/SQLAlchemy، PostgreSQL 16، React 18/Vite 5، Docker، pytest/Vitest/Playwright.

**Spec:** [التصميم الملزم](../specs/2026-10-23-verified-remediation-design.md).

## Global Constraints

- تطبيق ثوابت §3 من التصميم؛ المحافظة على الإصدارات الحالية وoptimizer runs=200، وحد الملف 25*1024*1024 بايت.
- لا يبدأ تنفيذ المنتج بمجرد كتابة هذه الخطة؛ جميع checkboxes أدناه غير منجزة.
- institutional لا يسمح بهوية تجريبية أو RPC بديل أو hashes مختلقة أو توقيع احتياطي.
- Evidence V2 ومجاله CYBER_AUDIT_EVIDENCE_V2 لا يتغيران؛ contract_version الجديد 2.1.0 وواجهة التحقق الجديدة /api/v3/evidence/verify.
- تأخير الحوكمة 86,400 ثانية، وTTL=259,200 ثانية، وموافقتان مستقلتان غير المقترح، وأربع هويات تصويت عند bootstrap.
- deployed bytecode<=24,000 بايت؛ لا استخدام allowUnlimitedContractSize=true لاجتياز التحقق.
- جميع مدد التنفيذ تقديرات عمل وليست تعهداً أو دليلاً على إغلاق مخاطر.

## 1. طريقة استخدام الخطة

اقرأ التصميم أولاً، نفذ R00، ثم اتبع الاعتمادات في الجدول. لا تنفذ الأرقام كتسلسل أعمى؛ توجد أعمال مستقلة يمكن تنفيذها بالتوازي بواسطة فريق حقيقي بعد تثبيت العقود المشتركة. طلب المستخدم الحالي هو إعداد الخطة؛ لم يُفوض نشر خارجي أو نقل بيانات حقيقية أو شراء خدمات.

لكل مهمة دورة مستقلة: اختبار يثبت الخلل، تشغيله والتأكد من فشل السلوك المقصود، إصلاح محدود، نجاح الاختبار والمجموعة ذات الصلة، مراجعة الفرق، ثم commit اختياري محصور بملفات المهمة. لا تؤخذ نتيجة قديمة بدلاً من الاختبار الأحمر. إذا كان الخلل قد أصلحه المستخدم بالفعل، يسجل الاختبار PASS_ALREADY_FIXED وتراجع كفاية الحماية قبل تجنب إصلاح مكرر.

أوامر الخادم موحدة من جذر المستودع: في PowerShell اضبط PYTHONPATH=./ai-engine لعملية الاختبار؛ السكربت scripts/run-python.js يختار المفسر، لكنه لا يغني عن تثبيت حزمة متطلبات المشروع في بيئة معزولة. في CI اضبط PYTHONPATH عبر env. أوامر الاختبارات الجديدة أدناه ستصبح قابلة للتنفيذ في مهامها؛ وجودها في الخطة لا يعني أنها موجودة الآن.

## 6. أدلة الإغلاق ومنع النجاح الزائف

كل docs/verification/remediation/Rxx.md يحتوي: commit + dirty diff hash، نظام التشغيل والإصدارات، أوامر الاختبار ومجلد تشغيلها وexit codes، الاختبار الأحمر قبل الإصلاح والأخضر بعده، ونتيجة full relevant suite، وما لم يُختبر وسببه، ودليل الحالة النهائية المستقل. لا تحفظ tokens/مفاتيح/ملفات عملاء في artifacts.

يجب أن يكون فشل regression بسبب السلوك الخاطئ المقصود؛ ImportError أو خدمة مفقودة ليسا اختباراً أحمر مقبولاً. الاختبارات الناجحة باستبدال RPC أو هوية المستخدم لا تغلق اختبار التكامل الحقيقي. عند تعذر بيئة لازمة تبقى المهمة BLOCKED_VALIDATION في سجل التنفيذ ولا تُعلن VERIFIED_FIXED.

اختبارات وظيفية سريعة في كل مهمة؛ حمل 30 دقيقة واستعادة كاملة في R19/R16، ثم إعادة لازمة فقط إذا أثر تعديل لاحق على المسار المقاس. عدد تحذيرات lint الحالي يُقاس؛ لا يُضبط السقف تلقائياً على نتيجة أسوأ، ولا يُشترط تنظيف 243 تحذيراً غير مرتبط لتبرير تأخير إصلاح P0.

## 7. الانتقال والرجوع

1. أصلح على branch محلي codex/verified-remediation إذا بدأ التنفيذ، بعد تثبيت تعديلات المستخدم؛ لا تنقلها أو تعمل reset تلقائياً.
2. أعد النشر محلياً ومرر بوابات الثقة قبل تغيير أي سجل مؤسسة حقيقية.
3. الترحيل الفعلي يوقف الكتابة مؤقتاً، يفرغ/يصالح outbox، يأخذ نسخة مثبتة، ويصدر خريطة deployment_id القديم والجديد مع cutover block. لا يعيد توقيع البيانات القديمة لتبدو موثقة حديثاً.
4. لا يُنفذ نشر خارجي أو تبديل إنتاجي ضمن إذن إعداد الخطة. عند طلبه لاحقاً، تعرض حزمة الترحيل والنسخة الاحتياطية والاختبارات أولاً.
5. إذا فشل cutover فالرجوع إلى read-only على البيانات القديمة، مع تعطيل verified والكتابات الحساسة؛ لا إعادة تفعيل bypass قديم لتوفير الخدمة. تُسجل المعاملات التي بُثت بالفعل وتُصالح قبل أي إعادة محاولة.
